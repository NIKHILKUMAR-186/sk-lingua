============================================================
READABILITY RULE
============================================================

The previous landing page became visually messy because too many visual elements competed for attention.

Therefore:

Every section must have a clear hierarchy.

Users should instantly understand:

WHAT IS THIS?
WHY SHOULD I CARE?
HOW DOES IT WORK?
WHAT SHOULD I DO NEXT?

Avoid:

- excessive text
- giant paragraphs
- too many badges
- too many floating elements
- excessive gradients
- excessive shadows
- excessive borders
- too many competing colors
- decorative elements behind important text

Visual sophistication must come from composition, not clutter.

============================================================
ANIMATION SYSTEM
============================================================

Use animations ONLY where they improve the experience.

Animations should be based on the interaction principles described in `design.md`.

Possible techniques include:

- text reveal
- word reveal
- character reveal
- fade + slide
- staggered entrance
- scroll-triggered reveal
- subtle parallax
- image movement
- hover elevation
- magnetic CTA
- floating elements
- smooth section transitions

But:

DO NOT use all of these everywhere.

Choose the animation that best fits each section.

Animation hierarchy:

1. Hero → strongest motion
2. Section transitions → subtle
3. Cards → micro-interactions
4. Buttons → responsive feedback
5. Background → very subtle

The page should remain readable even if animations are disabled.

============================================================
TEXT REVEAL
============================================================

If `design.md` supports text-reveal effects, use them strategically.

Good candidates:

- Hero headline
- Major section headings
- Key value propositions

Avoid animating every sentence.

Text should never become unreadable because of animation.

Respect:

`prefers-reduced-motion`

============================================================
PARALLAX
============================================================

Use parallax only where it creates meaningful depth.

Good candidates:

- hero visual
- background shapes
- product imagery
- floating mentor/session elements

Do NOT make the entire page move independently.

Avoid motion sickness.

Keep movement subtle.

============================================================
GLASSMORPHISM / CLAYMORPHISM / NEOMORPHISM
============================================================

Use these styles ONLY where they fit `design.md`.

Do not combine every visual trend.

For example:

Glassmorphism can be used for:

- floating navigation
- hero cards
- floating UI
- contextual overlays

Claymorphism can be used for:

- friendly learning illustrations
- feature cards
- mentor highlights

Neomorphism should be used sparingly.

The final design must still feel coherent.

PERFORMANCE
============================================================

- excessive DOM elements

- CSS transforms
- opacity
- GPU-friendly properties
- IntersectionObserver where appropriate
- existing project animation utilities

Do not add a dependency if the existing stack already provides the required capability.
